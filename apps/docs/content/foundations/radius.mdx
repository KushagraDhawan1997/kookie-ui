Kookie UI rounds corners from one palette and three roles. A component reads a role, never a palette step. Controls (buttons, inputs, badges) climb with the theme and become capsules at `full`. Surfaces and overlays (cards, popovers, dialogs) damp as the theme grows and never go pill.

The factor system is from [Radix Themes](https://www.radix-ui.com/themes). Kookie UI's values, roles and nesting rule are custom.

## Installation

```bash
npm install @kushagradhawan/kookie-ui
```

## Usage

Set `radius` on the Theme component. Every role moves from this one prop.

```tsx
import { Theme } from '@kushagradhawan/kookie-ui';

<Theme radius="medium"><YourApp /></Theme>
```

## Palette

Raw corners, times `--radius-factor`. `--radius-full` is 9999px at `full` and 0px below it.

```css
var(--radius-0)  /* 0px */
var(--radius-1)  /* 6px */
var(--radius-2)  /* 8px */
var(--radius-3)  /* 10px */
var(--radius-4)  /* 12px */
var(--radius-5)  /* 16px */
var(--radius-6)  /* 20px */
var(--radius-7)  /* 24px */
var(--radius-8)  /* 28px */
var(--radius-9)  /* 32px */
var(--radius-10) /* 40px */
var(--radius-full)
```

## Roles

Each role has four steps, one per size.

```css
var(--radius-control-1..4) /* palette 1 to 4; half the control height at full */
var(--radius-surface-1..4) /* 10, 16, 22, 28px: cards, popovers, menus, tables, panes */
var(--radius-overlay-1..4) /* 14, 20, 24, 28px: dialogs and sheets */
```

Surface and overlay steps are times `--radius-surface-factor`, so the px above are what they draw at `full`.

## Nesting

A surface inside a surface is concentric. Its corner is the outer corner minus the outer padding, never below 0. Card does this for you. At the default sizes the padding is larger than the corner, so a nested Card comes out square.

## Factors

Each theme sets both factors. Controls read `--radius-factor`, surfaces and overlays read `--radius-surface-factor`. The surface factor is capped at `1`, which is what keeps panels calm at the top of the scale.

```css
[data-radius='none']   { --radius-factor: 0;    --radius-surface-factor: 0;    }
[data-radius='small']  { --radius-factor: 0.75; --radius-surface-factor: 0.5;  }
[data-radius='medium'] { --radius-factor: 1;    --radius-surface-factor: 0.75; }
[data-radius='large']  { --radius-factor: 1.5;  --radius-surface-factor: 0.9;  }
[data-radius='full']   { --radius-factor: 2;    --radius-surface-factor: 1;    }
```

A surface at `full` is exactly as round as a surface at `medium`. Controls keep climbing past it.

## Mark Ceiling

Checkbox caps its corner at 40% of its own box, so at `full` it stays square and never reads as a Radio. Switch and Radio keep their pill and circle at every theme.

## Scale

### None

Sharp corners everywhere. Geometric, technical interfaces.

```tsx
<Theme radius="none"><YourApp /></Theme>
```

### Small

Tight rounding. Controls at 0.75x, surfaces at 0.5x.

```tsx
<Theme radius="small"><YourApp /></Theme>
```

### Medium

Standard rounding. Controls at 1x, surfaces at 0.75x.

```tsx
<Theme radius="medium"><YourApp /></Theme>
```

### Large

Prominent controls against steady surfaces. Controls at 1.5x, surfaces at 0.9x.

```tsx
<Theme radius="large"><YourApp /></Theme>
```

### Full

Pill-shaped controls inside near-square panels — the widest contrast the system offers, and the default. Controls at 2x plus pill, surfaces capped at 1x.

```tsx
<Theme radius="full"><YourApp /></Theme>
```

## Overrides

Components that accept a `radius` prop re-declare both factors for their subtree.

```tsx
<Theme radius="medium">
  <Button radius="full">Pill button</Button>
  <Accordion.Root radius="small">...</Accordion.Root>
</Theme>
```

In custom CSS, read the role that matches what you are drawing:

```css
.my-panel {
  border-radius: var(--radius-surface-2);
}

.my-control {
  border-radius: var(--radius-control-2);
}
```
