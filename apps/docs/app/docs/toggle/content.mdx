A toggle is a button with two states: pressing it turns something on, and pressing it again turns it off. It is a [Button](/docs/button) in every other respect and shows Button's pressed look while on. A setting in a list of preferences is a [Switch](/docs/switch), and picking one of several options is a [Segmented Control](/docs/segmented-control).

## Usage

```tsx showLineNumbers
import { Flex, Toggle } from '@kushagradhawan/kookie-ui';
import { HugeiconsIcon } from '@hugeicons/react';
import { TextBoldIcon, TextItalicIcon, TextUnderlineIcon } from '@hugeicons/core-free-icons';

export function FormattingBar() {
  return (
    <Flex gap="1">
      <Toggle iconOnly emphasis="quiet" aria-label="Bold" tooltip="Bold">
        <HugeiconsIcon icon={TextBoldIcon} strokeWidth={1.75} />
      </Toggle>
      <Toggle iconOnly emphasis="quiet" aria-label="Italic" tooltip="Italic">
        <HugeiconsIcon icon={TextItalicIcon} strokeWidth={1.75} />
      </Toggle>
      <Toggle iconOnly emphasis="quiet" aria-label="Underline" tooltip="Underline">
        <HugeiconsIcon icon={TextUnderlineIcon} strokeWidth={1.75} />
      </Toggle>
    </Flex>
  );
}
```

## Best practices

**Keep the label the same in both states.** "Bold" names the thing that is on or off, and the pressed look shows which. A label that changes from "Show" to "Hide" makes people guess whether it names the state or the action.

**Use a toggle for a state people turn on and off while they work.** Formatting, a filter, or a muted microphone fits. A saved preference belongs in a [Switch](/docs/switch).

**Use a Segmented Control when the options exclude each other.** Left, centre and right alignment are one choice, so a row of toggles would let people pick none or all three. A [Segmented Control](/docs/segmented-control) keeps exactly one selected.

**Make the pressed state easy to see.** In a toolbar, give toggles `emphasis="quiet"` so the pressed look stands out from the resting ones.

## Pressed state

A toggle manages its own state by default: set `defaultPressed` to start it on. To keep the state in your app, pass `pressed` with `onPressedChange`. A toggle with `pressed` and no `onPressedChange` can't change, and it warns in development.

```tsx
const [muted, setMuted] = React.useState(false);

<Toggle pressed={muted} onPressedChange={setMuted}>
  Mute
</Toggle>
```

## Examples

### Filter in a list header

A toggle with a label works as an on or off filter beside other controls. The list updates as soon as it changes.

```tsx
<Toggle defaultPressed={false} onPressedChange={setShowArchived}>
  <HugeiconsIcon icon={Archive01Icon} strokeWidth={1.75} />
  Show archived
</Toggle>
```

### Icon only

`iconOnly` makes the toggle square. It has no visible text, so the types require `aria-label` or `aria-labelledby`. Add `tooltip` so people who use a pointer can see the name too.

## Props

Toggle takes every [Button prop](/docs/button#props) except `as`, and these:

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `pressed` | `boolean` | | Whether the toggle is on, controlled |
| `defaultPressed` | `boolean` | `false` | Whether the toggle starts on |
| `onPressedChange` | `(pressed: boolean) => void` | | Fires with the new state |

Toggle also accepts every attribute of the HTML `button` element.

## Accessibility

| Key | Action |
| --- | --- |
| Enter or Space | Turns the toggle on or off |
| Tab | Moves focus to the next control |

- **Name:** A screen reader announces the label. An icon-only toggle announces its `aria-label`, which the types require.
- **State:** The toggle sets `aria-pressed`, so a screen reader announces it as a toggle button that is pressed or not pressed.
- **Focus:** The focus ring shows for the keyboard only, as on a Button.
