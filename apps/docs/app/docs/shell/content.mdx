Shell is the frame of an application. It places a header, navigation, the main content, an inspector and a bottom panel on a CSS grid. Each pane holds its own open state, follows the window when nobody has touched it, and becomes an overlay where there is no room for it.

## Installation

```bash
npm install @kushagradhawan/kookie-ui
```

## Usage

```tsx
import { Shell } from '@kushagradhawan/kookie-ui';

export function App() {
  return (
    <Shell.Root>
      <Shell.Sidebar>
        <nav>Navigation</nav>
      </Shell.Sidebar>
      <Shell.Content>Main content</Shell.Content>
    </Shell.Root>
  );
}
```

On a window 768px or wider the sidebar sits in the frame and is open. Below 768px it is an overlay and is closed until a `Shell.Trigger` opens it.

## Anatomy

```tsx showLineNumbers
<Shell.Root>
  <Shell.Header>{/* the top row */}</Shell.Header>
  <Shell.Rail>{/* a narrow column of icons */}</Shell.Rail>
  <Shell.Panel>{/* the navigation the rail opens */}</Shell.Panel>
  <Shell.Sidebar>{/* one navigation column, in place of Rail and Panel */}</Shell.Sidebar>
  <Shell.Content>{/* the work area */}</Shell.Content>
  <Shell.Inspector>{/* details at the inline end */}</Shell.Inspector>
  <Shell.Bottom>{/* a panel along the bottom */}</Shell.Bottom>
  <Shell.Trigger target="sidebar">{/* a button that drives a pane */}</Shell.Trigger>
</Shell.Root>
```

Every part is optional except `Shell.Content`. The Root renders its children in the order you write them, so other elements can sit between the parts, and a pane can be wrapped in another element. Each pane takes its own place on the grid.

### Trigger

`Shell.Trigger` is a `<button>`. Wrap it with `IconButton` or `Button` through `asChild` to style it.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `target` | `'rail' \| 'panel' \| 'sidebar' \| 'inspector' \| 'bottom'` | | The pane it drives. |
| `action` | `'toggle' \| 'expand' \| 'collapse'` | `'toggle'` | What a press does. |

The trigger renders `type="button"`, `aria-controls` (the pane's id) and `aria-expanded`. Your `onClick` runs first. Call `event.preventDefault()` in it to cancel the trigger's action.

### Resize

Panel, Sidebar, Inspector and Bottom take these props.

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `resizable` | `boolean` | `false` | Shows a handle on the pane's inner edge. |
| `size` | `number \| string` | | The size, when you control it. |
| `defaultSize` | `number \| string` | | The starting size. |
| `onSizeChange` | `(size, { reason }) => void` | | Called with the new size. `reason` is `'init'`, `'resize'` or `'controlled'`. |
| `sizeUpdate` | `'throttle' \| 'debounce'` | | How often `onSizeChange` is called during a drag. |
| `sizeUpdateMs` | `number` | `50` | The interval for `sizeUpdate`. |
| `minSize` | `number` | per pane | The smallest size, in pixels. |
| `maxSize` | `number` | per pane | The largest size, in pixels. A drag also stops before the handle leaves the frame. |
| `collapsible` | `boolean` | `true` | A double-click on the handle opens and closes the pane. |
| `onResizeStart` | `(size) => void` | | Called when a drag starts. |
| `onResize` | `(size) => void` | | Called during a drag, at most once per animation frame, and once more with the final size. |
| `onResizeEnd` | `(size) => void` | | Called when a drag ends. |

## Presentation

`presentation` says how a pane sits in the frame. It takes one value or a responsive object.

### Fixed

The pane takes its own column or row, and the content is narrower by its size.

### Overlay

The pane covers the frame. A scrim covers everything else, the rest of the frame is `inert`, focus moves into the pane, and the page does not scroll. Escape or a press on the scrim closes it. An overlay that nobody has opened stays closed.

### Stacked

The pane sits over the content without a scrim and without taking space from it.

## States

### Untouched

A pane with no `open`, `defaultOpen`, `state` or `defaultState` is untouched. It renders `data-state="auto"`, and the stylesheet shows or hides it at each breakpoint:

- Rail and Sidebar are open where they are in the frame and closed where they are an overlay.
- Panel, Inspector and Bottom are closed.

A responsive `defaultOpen` or `defaultState` also leaves the pane untouched, with your object as the answer at each breakpoint:

```tsx
<Shell.Inspector defaultOpen={{ initial: false, lg: true }}>…</Shell.Inspector>
```

The server HTML already carries the answer for every breakpoint, so the first paint is right before any script runs.

### Touched

When a user opens or closes a pane, it keeps that state at every width. A single-value `defaultOpen` or `defaultState` starts the pane in that state in the same way.

### Controlled

Pass `open` (or `state` on the Sidebar) with its change handler. The pane shows what you pass. Do not pass both the controlled prop and its default.

### Callbacks

`onOpenChange` and `onStateChange` are called only when a user acts. `reason` is:

- `'toggle'` for a Trigger, a double-click on the handle, or a drag past `collapseThreshold`.
- `'dismiss'` for Escape or a press on the scrim.

They are not called on mount, and not called when the window crosses a breakpoint.

### Sidebar thin

`thin` shows the sidebar at `thinSize`. With `toggleModes="both"` a trigger goes collapsed, thin, expanded. With `toggleModes="single"` it goes between collapsed and the sidebar's open state (thin if `defaultState` is `"thin"`, else expanded).

## Examples

### Header and Sidebar

```tsx showLineNumbers
<Shell.Root>
  <Shell.Header>
    <Flex align="center" gap="2" px="3" height="100%">
      <IconButton variant="ghost" color="gray" aria-label="Toggle navigation" asChild>
        <Shell.Trigger target="sidebar">
          <HugeiconsIcon icon={SidebarLeft01Icon} strokeWidth={1.75} />
        </Shell.Trigger>
      </IconButton>
      <Text weight="medium">Projects</Text>
    </Flex>
  </Shell.Header>
  <Shell.Sidebar>
    <nav>Navigation</nav>
  </Shell.Sidebar>
  <Shell.Content>Main content</Shell.Content>
</Shell.Root>
```

### Rail and Panel

```tsx showLineNumbers
<Shell.Root>
  <Shell.Rail>
    <IconButton variant="ghost" color="gray" aria-label="Toggle panel" asChild>
      <Shell.Trigger target="panel">
        <HugeiconsIcon icon={SidebarLeft01Icon} strokeWidth={1.75} />
      </Shell.Trigger>
    </IconButton>
  </Shell.Rail>
  <Shell.Panel defaultOpen={{ initial: false, md: true }}>
    <nav>Navigation</nav>
  </Shell.Panel>
  <Shell.Content>Main content</Shell.Content>
</Shell.Root>
```

The rail and the panel do not drive each other. To close the panel when the rail closes, write it:

```tsx showLineNumbers
const [railOpen, setRailOpen] = React.useState(true);
const [panelOpen, setPanelOpen] = React.useState(true);

<Shell.Rail
  open={railOpen}
  onOpenChange={(open) => {
    setRailOpen(open);
    if (!open) setPanelOpen(false);
  }}
/>
<Shell.Panel open={panelOpen} onOpenChange={setPanelOpen} />
```

### Resizable Inspector

```tsx showLineNumbers
const [width, setWidth] = React.useState(320);

<Shell.Inspector
  resizable
  size={width}
  onSizeChange={setWidth}
  minSize={240}
  maxSize={480}
>
  Properties
</Shell.Inspector>
```

Keep the size in your own state to save it between visits.

### Controlled Sidebar

```tsx showLineNumbers
const [state, setState] = React.useState<'collapsed' | 'thin' | 'expanded'>('expanded');

<Shell.Sidebar state={state} onStateChange={setState}>
  <nav>Navigation</nav>
</Shell.Sidebar>
```

## Inset

`inset` lifts a pane off the frame. The pane gets a margin, rounded corners and a shadow, and the frame paints a gray backdrop behind the middle row. Two inset panes side by side share one gap.

```tsx
<Shell.Root>
  <Shell.Sidebar inset>…</Shell.Sidebar>
  <Shell.Content inset>…</Shell.Content>
</Shell.Root>
```

Change the gap on the Root:

```css
.rt-ShellRoot {
  --shell-inset-gap: var(--space-3);
}
```

## Responsive

`presentation`, `defaultOpen` and `defaultState` take responsive objects. A breakpoint takes the value of the largest key at or below it.

| Breakpoint | Width |
| ---------- | ----- |
| `initial` | below 520px |
| `xs` | 520px |
| `sm` | 768px |
| `md` | 1024px |
| `lg` | 1280px |
| `xl` | 1640px |

The values are written to the pane as `data-presentation-<bp>` and `data-auto-<bp>`, and the stylesheet reads them at these widths.

## Accessibility

- `Shell.Header` renders `<header>` and `Shell.Content` renders `<main>`.
- `Shell.Trigger` sets `aria-controls` and `aria-expanded`.
- An open overlay makes the rest of the frame `inert`, moves focus into the pane, and returns focus when the pane closes.
- Escape closes open overlays. It is handled on the Root, so a dialog opened from inside a pane keeps its own Escape.
- The resize handle is a focusable `role="separator"` with `aria-controls`, `aria-valuenow`, `aria-valuemin` and `aria-valuemax`. The arrow keys move it by 8px (32px with Shift), and Home and End go to the limits. It shows a focus line on `:focus-visible`.

## Changelog

### 0.8.0

- The Shell is rebuilt on kookie-ui-v2's model. See the package changelog for the full list.
- Untouched panes follow the window through the stylesheet. Callbacks fire only when a user acts.
- Sidebar and Inspector are overlays below 768px.
